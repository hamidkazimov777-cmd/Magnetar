# Тест-сценарий Magnetar

> Как убедиться, что приложение работает так, как задумано. Актуально на
> **2026-08-24**. Устройство и термины — в [OVERVIEW.md](OVERVIEW.md).

Проверка идёт на трёх уровнях: **машинные тесты** (запускаются командой),
**контрольный прогон против голого API** (эталон, с которым сравнивают
приложение) и **живой прогон в приложении** (проходит человек).

---

## 0. Прогон сборки (smoke) + E2E-регрессия

Быстрый автоматический прогон после каждой сборки — одна команда:

```bash
npm run smoke
```

Делает без ключей и без сети: `tsc --noEmit` → `npm run build` →
`cargo test` → генерация детерминированной фикстуры
`~/Documents/Magnetar/_fixture` (широкое дерево `bulk/` + глубокая цепочка
`deep/…`, Rust-крейт с 300 намеренными ошибками) → печать короткого чеклиста.

Фикстура лежит в **видимой** папке (не в скрытой), поэтому открывается обычным
выбором папки: ⌘K → «Открыть папку» → Documents → Magnetar → `_fixture`.

Полный ручной E2E-сценарий с ожидаемым результатом каждого шага —
см. [E2E_REGRESSION.md](E2E_REGRESSION.md).

Живой API-прогон — **отдельно и вручную** (тратит токены):
`node scripts/e2e-test.mjs` и `node scripts/agent-e2e.mjs "<задача>"`.

## A. Машинные тесты

```bash
npx tsc --noEmit && npm run build          # фронтенд
cd src-tauri && cargo test                 # Rust: 9 тестов
```

Что покрыто:

| Тест | Что доказывает |
|---|---|
| `workspace::memory_tables_round_trip` | Схема памяти: факты, решения, расхождения пишутся и читаются; обновление по id не плодит дубликат; удалённое остаётся удалённым; проекты не смешиваются; новые колонки не сдвинули индексы |
| `utf8::*` (4 теста) | Кириллица не рвётся на границе сетевого чанка, поток не застревает на битом байте |
| `tools::background_child_holding_stdout_does_not_hang` | Фоновый процесс, держащий stdout, не вешает прогон до таймаута |
| `tools::ordinary_command_returns_complete_output` | Обычная команда возвращает вывод целиком |
| `tools::oversized_output_is_capped_during_execution` | Вывод `run_bash` ограничен `MAX_BASH_BYTES` во время выполнения, а не после; переполнение помечается |
| `tools::git_exec_runs_a_quick_command` | `git_exec` выполняет быстрый сабкоманд и возвращает вывод |

Полнота переводов (должно печатать пустые списки) — скрипт в разделе 8
`NEXT_TASK_FILES.md`.

## B. Контрольный прогон против голого API

Смысл: прогнать **одну и ту же задачу** двумя путями — через голый HTTP API
провайдера и через приложение — и сравнить. Расхождение означает баг обвязки, а
не каприз модели.

**Подготовка** (ключи в git не попадают, файл в `.gitignore`):

```bash
mkdir -p .magnetar-test && cat > .magnetar-test/keys.json <<'JSON'
[{ "name": "Kimi", "baseUrl": "https://api.moonshot.ai/v1", "key": "sk-…", "model": "kimi-k2.7-code" }]
JSON
```

**Запуск:**

```bash
node scripts/agent-e2e.mjs "<задача>" /tmp/magnetar-e2e
```

Скрипт берёт **системный промпт и определения инструментов прямо из
`src/lib/agent.ts`**, а не копирует их: копия разъезжается, и контрольная группа
перестаёт быть контрольной.

**Что сравнивать** — не тексты (два прогона LLM никогда не совпадут дословно), а
поведение:

| Показатель | О чём говорит расхождение |
|---|---|
| Число вызовов инструментов | Агент топчется — виновата обвязка |
| Вызовы нативные или напечатаны текстом | Определения инструментов или промпт |
| Входные токены | Отбор памяти и кэш промпта |
| Ошибки провайдера | Формат нашего тела запроса |
| Что реально создалось в папке | Дошло ли исполнение инструментов |

**Эталон от 2026-08-20** (задача «телеграм-бот с /start и /time», Kimi
`kimi-k2.7-code`, пустая папка): 5 ходов модели, 6 вызовов, 15 секунд, вход
8993 / выход 1029, три файла. Приложение на той же задаче дало ровно ту же
последовательность вызовов.

## C. Живой прогон в приложении

### 1. Подключение

Ключ-иконка внизу рейла → провайдер → ключ → «Проверить».
**Ожидание:** модели появляются в переключателе сверху.

Затем Настройки → «Модель для фоновых задач» → выбрать провайдера, потом модель.
**Ожидание:** список моделей грузится в момент выбора провайдера; если провайдер
список не отдаёт — видна причина и поле для ручного ввода id.

⚠️ Без рабочей фоновой модели память не собирается — это первое, что нужно
проверить, если память осталась пустой.

### 2. Память из настоящего проекта

Открыть папку с реальным проектом (где есть `package.json` / `Cargo.toml`).

**Ожидание:**
- дорожка «Агент» включается сама, строится индекс;
- в панели «Память проекта» появляются факты с пометкой **«извлечено:
  package.json»**;
- часть фактов сразу получает статус **«проверено» с датой** — сработала
  автоматическая grep-проверка;
- в журнале памяти нет красных строк.

Кнопка **«Проверить факты»** запускает и дорогие проверки; показывает
`подтверждено · опровергнуто · продержалось`.

⚠️ Пустая папка — не тест памяти: там читать нечего, и приложение осознанно
оставит память пустой, написав в журнал «Читать нечего».

### 3. Расхождение памяти и кода

Вписать в память заведомо ложный факт (кнопка «+» в панели памяти), например
`Данные хранятся в PostgreSQL`. Затем попросить агента: «Проверь по коду, где
хранятся данные. Сверься с памятью проекта».

**Ожидание:** агент читает код, вызывает `flag_memory`, **диалога не появляется**,
в панели памяти растёт счётчик расхождений. Разбор — на странице «Проекты».

### 4. Агент спрашивает в момент решения

Задача с настоящей развилкой: «Добавь хранение истории прогонов агента — выбери,
где хранить».

**Ожидание:** появляется вопрос с вариантами и рекомендацией; ответ становится
записью в журнале решений (дата, причина, отвергнутые варианты, коммит).

### 5. Две дорожки и передача промпта

1. Вкладка «Обсуждение», выбрать **другую** модель.
2. Попросить написать промпт для агентской модели.
3. Нажать **«В агента»** под ответом.

**Ожидание:** открывается вкладка «Агент», возвращается её модель, текст попадает
**в поле ввода без отправки**. После работы агента возврат в «Обсуждение»
показывает прежнюю модель и прежнюю переписку.

**Отдельно проверить:** в «Обсуждении» спросить «какой у нас стек» — модель
должна ответить из памяти проекта, ничего не читая. «Не вижу проект» = память в
эту дорожку не дошла.

### 6. Защита агента

- Попросить удалить файл или выполнить `rm -rf` → **подтверждение обязано
  появиться** даже при включённом авто-применении правок.
- Во время долгого прогона написать сообщение → агент отвечает на него на
  следующем ходу, второй прогон не стартует.
- «Стоп» во время генерации → ход прекращается сразу, а не дописывается.

### 7. Вложения

Сделать скриншот (⌘⇧4) и перетащить прямо в окно.
**Ожидание:** панель агента открывается сама, файл появляется во вложениях.
Текстовый файл (`.log`, `.py`) уходит содержимым, а не мусором.

### 8. Диагностика, если что-то не так

1. Кнопка-глаз в шапке панели агента → «Что видит модель»: дошла ли память.
2. Журнал памяти внизу панели: что записалось и что упало.
3. Кнопка **«Скачать снимок памяти»** — один JSON со всем состоянием памяти
   (без ключей), его удобно отдать на разбор.

### 9. Редактор: ошибки, замена, переход к файлу

- Панель «Проблемы» → «Запустить все». **Ожидание:** ошибки не только в списке,
  но и подчёркнуты прямо в коде; клик по проблеме открывает файл на строке.
- Панель поиска → ввести строку, которая точно встречается в нескольких файлах
  → «Заменить» → «Найти точные вхождения». **Ожидание:** список файлов с числом
  вхождений и превью строки; галочки снимаются; замена происходит только после
  нажатия кнопки. Регистр учитывается: `Fact` и `fact` — разные строки.
- **⌘P** → часть имени файла. **Ожидание:** список файлов проекта с нечётким
  поиском, Enter открывает файл во вкладке.

### 10. Субагенты

- **Состав.** Кнопка «Помощники» рядом с дорожками (видна в агентской дорожке) →
  выбрать модели у разных провайдеров. **Ожидание:** чипы выбранного, счётчик на
  кнопке, ползунок параллельности там же.
- **Делегирование.** Задача из независимых кусков («три страницы-заглушки, у
  каждой свой файл»). **Ожидание:** `delegate → N` в трейсе, панель «Помощники»
  с дорожками, у каждой видна **своя** модель, если выбрано несколько.
- **Аренда файлов.** Задача, где два куска трогают один файл. **Ожидание:**
  второй помощник не стартует, главный получает объяснение с именем файла.
- **Границы.** Помощник не делегирует дальше, не спрашивает пользователя, а
  разрушительное получает отказ со статусом «заблокировано защитой» — не
  «отклонено пользователем».

### 11. Работа без открытой папки

- Не открывая папку, попросить создать файлы. **Ожидание:** агент **не ищет**
  проект по диску (никаких `find /Users`), а вызывает `new_project` → диалог
  «Создать папку проекта» с путём `~/Documents/Magnetar/<имя>`.
- «Создать и открыть» → папка создаётся, **открывается как проект** (появляется
  дерево, индекс, память) и агент продолжает работу в ней.
- «Отклонить» → одна строка о том, что нужно открыть папку, и остановка.
