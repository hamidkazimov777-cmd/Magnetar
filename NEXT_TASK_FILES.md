## Как работать (как предыдущий ассистент)

1. **Сначала прочитай `HANDOFF.md` целиком** (журнал, Записи 1–12), затем `README.md`
   и `START_HERE_PROMPT.md`. Освой `src-tauri/src/` и `src/`.
2. Стек не менять без согласия. Секреты — только в macOS Keychain, в файлы/гит не
   писать. Наружу — только к настроенным API, ничего «домой».
3. НЕ строить скрытую автоматизацию подписочных ИИ через браузер (обход ToS).
4. НЕ прятать главное окно на старте (`visible:false`+`show()` ломает релиз — см. Запись 12).
5. Проверки перед коммитом: `cargo check` (в `src-tauri`), `npx tsc --noEmit`,
   `npm run build`. Dev: `npm run tauri dev` (`source $HOME/.cargo/env` если надо).
   Релиз: `npm run tauri build` → `src-tauri/target/release/bundle/`.
6. Работай автономно; спрашивай только по архитектуре или секретам.
7. **Когда закончишь/остановят — допиши новую запись в конец `HANDOFF.md`**
   (что сделал / что не доделано / следующий шаг). Старое не удаляй.
8. Держи i18n: любую новую строку UI клади во ВСЕ три словаря `src/lib/i18n.ts`
   (ru/en/es) и используй `t('key')`.

## ЗАДАЧА: обмен файлами в обе стороны (мультимодальность)

Нужно, чтобы **пользователь мог отправлять файлы модели** (фото, PDF, текст и т.п.)
и **модель могла присылать файлы пользователю** (изображения, PDF, сгенерированные
файлы) — как это обычно умеют ИИ.

### Часть A. Пользователь → модель (вложения)

- **UI (Composer):** кнопка-скрепка + **drag-and-drop** файла в чат + **вставка
  изображения из буфера** (Ctrl/Cmd+V). Показывать превью прикреплённых файлов
  (миниатюра для картинок, иконка+имя для остального) с удалением до отправки.
- **Открытие файлов:** через `@tauri-apps/plugin-dialog` (open) + `plugin-fs`
  (чтение). Добавить плагины в Cargo.toml, `lib.rs` и capabilities.
- **Изображения → vision-моделям:** OpenAI-совместимый формат — сообщение с
  `content` как массивом блоков:
  `[{type:"text",text:...},{type:"image_url",image_url:{url:"data:image/png;base64,..."}}]`.
  ⚠️ Сейчас `ChatMessage.content` — простая строка и в `ChatParams`, и в каноне.
  Нужно расширить модель до мультимодального контента (текст + вложения), не сломав
  существующий текстовый путь и handoff-резюме. Аккуратно: адаптеры
  (`openai_compat.rs`, `gigachat.rs`) сериализуют канон в свой формат.
- **PDF / текстовые файлы:** прагматично — извлекать текст локально и подкладывать
  в контекст (для PDF — Rust-крейт `pdf-extract`/`lopdf` или JS `pdf.js`;
  для txt/кода — просто читать). Помечать в сообщении, что это вложенный файл.
- **GigaChat:** у него свой upload — `POST /files` (multipart), затем ссылка на
  `attachments` в запросе чата. Реализуй отдельно в `gigachat.rs` (не как OpenAI).
  Если модель не vision — деградируй корректно (текст/описание).
- **Канон/БД:** сохранять вложения (файл в app-data-dir + ссылка в мете сообщения),
  чтобы переживало перезапуск. Расширить схему `messages` (например колонка
  `attachments` JSON) с best-effort миграцией, как в `db.rs`.

### Часть B. Модель → пользователь (файлы)

- **Агентский инструмент `attach_file(path)`** (в дополнение к `write_file`): помечает
  файл как «отправленный пользователю». В чате рендерить **карточку файла**
  (иконка/превью, имя, размер) с кнопками **«Открыть»** (через уже подключённый
  `opener`-плагин / `revealItemInDir`) и **«Сохранить как…»** (`plugin-dialog` save).
- **Картинки от модели:** если провайдер вернул изображение (image-gen или в ответе
  data-URI/URL) — рендерить инлайн + кнопка сохранить.
- Отрисовку встроить в `Message.tsx` (сейчас там markdown-рендер): распознавать
  вложения сообщения и показывать карточки/превью.
- i18n подписи (RU/EN/ES) для «Открыть», «Сохранить», «Прикрепить файл» и т.п.

### Приёмка

- Можно перетащить фото в чат и спросить «что на картинке?» → vision-модель
  отвечает (проверь на OpenAI-совместимой vision-модели, напр. через OpenRouter).
- Модель в режиме «Агент» может создать файл и «прислать» его карточкой, которую
  можно открыть/сохранить.
- Всё компилируется (`cargo check`/`tsc`/`build`), работает офлайн, секреты в Keychain.
- Дописана новая запись в `HANDOFF.md`.

Начни с чтения `HANDOFF.md`, предложи короткий план (какие файлы трогаешь,
как расширяешь модель контента) и приступай.

## Актуализация — 2026-08-19

**Важно:** приведённый выше промт об «Обмене файлами» устарел как активная задача:
основная мультимодальность уже реализована (см. HANDOFF, Записи 13 и 16). Он
сохранён только как исторический контекст и не должен восприниматься как backlog.

### Текущее состояние за несколько минут

- Magnetar — Tauri v2 + React/TS + Tailwind v4 desktop AI IDE: BYOK/Keychain,
  SQLite-канон чатов и подключений, OpenAI-compatible + GigaChat, agent/tools,
  память проекта, CodeMirror editor, Git, PTY terminal, local BM25 search.
- Первый запуск ведёт через два видимых шага в пустом чате: подключить модель и
  открыть папку; Code автоматически анализирует папку в Project Memory.
- Навигация разделена на чаты/проектный слой и отдельную IDE-группу Workspace
  (Code, Git, Terminal). Интерфейс поддерживает RU/EN/ES; новые строки обязаны
  появляться во всех трёх словарях `src/lib/i18n.ts`.
- Иконка и in-app знак используют пользовательский PNG:
  `src/assets/magnetar-icon.png`; не заменять SVG-логотипом.

### Важные файлы и правила

- `src/App.tsx` — layout и переключение зон.
- `src/components/ChatView.tsx` — чат, onboarding, agent/stream flow.
- `src/components/Sidebar.tsx` — информационная архитектура.
- `src/components/EditorView.tsx`, `GitView.tsx`, `TerminalView.tsx` — IDE triad.
- `src/lib/store.ts`, `db.ts`, `memory.ts`, `handoff.ts`, `agent.ts` — канон,
  память и выполнение агента.
- `src-tauri/src/` — Rust-команды, SQLite, провайдеры, PTY, инструменты, BM25.
- Секреты только в macOS Keychain. Не автоматизировать подписочные веб-сервисы и
  не использовать `kill -9` для приложения. Не делать окно невидимым на старте.
