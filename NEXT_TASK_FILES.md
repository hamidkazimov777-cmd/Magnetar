## 0. Текущий фокус: внешний аудит производительности

Работа ведётся строго по приоритетам внешнего аудита. Закрыто:

- **P0.1** — мемоизация сообщений чата и устранение лишних ререндеров.
  - `Message` обёрнут в `React.memo`.
  - `ChatView` передаёт стабильный `onEdit`.
  - Транскрипт вынесен в `ChatTranscript`, `ChatView` не ререндерится на каждый токен.
- **P0.2** — перевод файловых операций на `blocking`/`background` потоки.
  - Семь файловых Tauri-команд переведены с синхронных `pub fn` на
    `pub async fn` + `blocking()`: `tool_read_file`, `tool_list_dir`,
    `tool_write_file`, `tool_delete_file`, `tool_edit_file`,
    `editor_read_file`, `create_project_dir`.
  - Крупное чтение/запись/листинг файлов больше не блокирует главный поток.
- **P0.3** — ограничение буферов `run_bash` во время выполнения.
  - `pump` теперь обрезает stdout/stderr на уровне `MAX_BASH_BYTES` по мере
    накопления (флаг переполнения), а не после завершения — `yes`/`npm install`
    больше не раздувают память на 600 с.
- **P0.4** — таймаут для `git_exec`.
  - Зависший `git` (prompt кредов, сеть) убивается через `GIT_TIMEOUT_SECS`
    (120 с) с убийством всей группы процессов; вывод дренируется ограниченно.
- **P1.5** — виртуализация чата.
  - `ChatTranscript` переведён на `@tanstack/react-virtual` (динамическая
    высота строк через `measureElement`): в DOM только видимое окно + overscan.
  - Автоскролл к последнему сообщению и баннер ошибки (как футер-элемент)
    сохранены. Новая зависимость: `@tanstack/react-virtual`.
- **P1.6** — виртуализация дерева файлов.
  - `ExplorerPanel` сплющивает раскрытое поддерево в плоский список и
    виртуализирует его через `@tanstack/react-virtual` (динамическая высота
    через `measureElement`, `overscan: 12`).
  - Git-статус и подсветка активного файла считаются только для смонтированных
    (видимых) строк. Ленивая загрузка, раскрытие/свёртка, «пустая папка»,
    скелетон и сортировка сохранены.
- **P1.7** — виртуализация списка проблем.
  - `ProblemsPanel` сплющивает «проверки + проблемы» в плоский список и
    виртуализирует его через `@tanstack/react-virtual` (динамическая высота
    через `measureElement`, `overscan: 8`).
  - В DOM только видимое окно; раскрытие/свёртка, запуск, клик по проблеме
    (`revealInFile`), «чисто» и сырой вывод сохранены.
- **P1.8** — ленивая загрузка Monaco.
  - `src/lib/monaco.ts` больше не делает статический
    `import * as monaco from "monaco-editor"`; движок грузится по требованию
    через мемоизированный `loadMonaco()` (динамический `import`, воркеры,
    темы, TS-дефолты, `loader.config`).
  - `main.tsx` убрал eager-импорт; `EditorArea` гейтит рендер редактора на
    `monacoReady`; `markers.ts::syncCheckMarkers` стал async.
  - Главный бандл упал с ~5.3 МБ до ~1.4 МБ, Monaco — отдельный чанк.
- **P1.9** — оптимизация поиска файлов в Composer.
  - `src/lib/mentions.ts::rankFiles` больше не делает `toLowerCase()` +
    `split("/")` для каждого файла на каждый ввод символа: добавлен
    мемоизированный индекс `FileEntry` (`path`/`lower`/`base`), кэшируемый по
    идентичности массива файлов.
  - Ранжирование и сигнатура не менялись; выигрыш получают `@`-пикер в
    Composer и ⌘P в CommandPalette (обе точки используют `rankFiles`).
- **P2.10** — автоочистка PTY.
  - `src-tauri/src/pty.rs`: reader-поток после завершения (EOF/ошибка/пропал
    канал) сам убирает сессию из `SESSIONS` и делает `child.kill()` +
    `child.wait()` (reap). `spawn` регистрирует сессию до запуска потока.
  - `kill()` тоже теперь `wait()`-ит после `kill()` — явное завершение не
    оставляет зомби. Закрытый терминал больше не течёт процессом/записью.

Следующая задача: **P2.11** — улучшение SQLite настроек (`src-tauri/src/db.rs`).

## 1. Что это

**Magnetar** — десктопное macOS-приложение: локальная AI-среда разработки
(BYOK — любая модель по ключу пользователя) с кодом, Git и терминалом в одном
окне. Репозиторий: `/Users/hamidkazimov/Magnetar`,
`git@github.com:hamidkazimov777-cmd/Magnetar.git`.

**Стек зафиксирован, не менять без согласия пользователя:**
Tauri v2 (Rust) + React 19 + TypeScript + Tailwind v4 + zustand + SQLite
(`rusqlite`, bundled) + macOS Keychain (`security-framework`).

## 2. Жёсткие правила (нарушение = регресс)

1. **Секреты — в `secrets.json` (app data dir, права 0600), НЕ в Keychain.**
   Изменено в Записи 44 по прямой просьбе владельца: macOS привязывает ACL
   записи Keychain к подписи кода, поэтому каждая пересборка вызывала запрос
   пароля, и «Разрешать всегда» не запоминалось. `keychain.rs` теперь файловое
   хранилище с одноразовой миграцией старых ключей из Keychain. Файл **не
   зашифрован** — осознанный компромисс уровня `~/.aws/credentials`.
   По-прежнему нельзя: класть ключи в SQLite, localStorage или git.
2. **Наружу — только к API, которые настроил пользователь.** Никакой телеметрии.
3. **Не строить скрытую автоматизацию подписочных ИИ** (ChatGPT/Claude/Gemini)
   через браузер — это обход ToS. Легальный путь уже реализован: встроенное
   браузер-окно + ручной «мост контекста».
4. **Не прятать главное окно на старте** (`visible:false` + `show()` ломает
   релизную сборку — см. Запись 12).
5. **Не убивать приложение `kill -9`** — webview не флашит состояние.
6. **i18n: новый ключ — сразу в ru + en + es** (`src/lib/i18n.ts`). Проверка
   полноты — скриптом из раздела 8.
7. **Новые глобальные CSS-классы — только внутрь `@layer components`** в
   `src/index.css`. Вне слоя они перебивают Tailwind-утилиты и ломают вёрстку.
8. **Шаги агента (`agentTrace`) не персистить** — это процесс, а не канон.
   Правки файлов (`store.changes`) — тоже транзиентные: они про текущий прогон.
9. **Канон хранит то, что напечатал пользователь.** Слэш-команды разворачиваются
   в инструкцию, которая уходит модели через system-промпт, а не подменяет текст
   сообщения в истории (см. Запись 35).
10. **`trustCommands` не персистить** — доверие командам действует только до
    перезапуска приложения.
11. **Две дорожки, а не тумблер.** Беседа принадлежит дорожке (`session.track`):
    `agent` — с инструментами, `chat` — без них. Дорожка хранится в БД, модель и
    провайдер живут на уровне сессии, поэтому переключение вкладки возвращает ту
    модель, с которой там говорили. `store.agentMode` — только зеркало активной
    дорожки для UI, писать в него напрямую нельзя: `setAgentMode` вызывает
    `switchTrack`. Память проекта уходит **в обе** дорожки, инструменты — только
    в агентскую. Не сливать дорожки в один транскрипт: обсуждение и шаги
    инструментов перемешиваются, и найти договорённость через час невозможно
    (Запись 51).
12. **Ссылки — только через `lib/links.ts`.** `<a href>` в webview навигирует
    окно приложения: клик по ссылке подменял весь Magnetar страницей, и крестик
    закрывал приложение (Запись 39). Глобальный перехватчик уже стоит в
    `App.tsx`; localhost открывается отдельным окном превью, остальное — в
    системном браузере. Не добавлять `target="_blank"` и `window.open`.
13. **Долгие Tauri-команды — только `async` + `blocking()`.** Синхронная
    `#[tauri::command] pub fn` выполняется в главном потоке и вешает всё окно.
    Так `run_bash` с таймаутом 600 с зависил приложение на 10 минут (Запись 37).
    Через `blocking()` уже проведены: `tool_run_bash`, `git_exec`, `tool_grep`,
    `index_build`, `index_search`, `list_project_files`, `extract_pdf_text`.
    Синхронными могут остаться только быстрые SQLite/Keychain-вызовы.
14. **Фоновые задачи — только через `cheapModel()`** (`lib/memory.ts`). Он
    уважает настройку «Модель для фоновых задач» и пропускает модели, которые
    провайдер уже отверг. Раньше в `handoff.ts` жила вторая копия эвристики с
    другими критериями — из-за неё память и граф знаний уходили на разные
    модели, а недоступная модель выбиралась вечно (404 «No such model»,
    Запись 41). Не заводить новых эвристик подбора.
15. **Ошибки анализа памяти не глушить.** `analyzeFolderIntoMemory` пишет
    причину в `store.memoryError`, Explorer её показывает. Тихий `return null`
    приводил к пустому проекту «New Project» без единого сигнала пользователю.
16. **Любая фоновая запись в память обязана отчитаться** через
    `store.logMemory({kind,status,detail})`. Журнал видно в панели «Память
    проекта». До Записи 42 все шесть задач глушили ошибки в `catch {}`, и
    пустая память выглядела как поломка без объяснений.
17. **Тема живёт на `<html data-theme>`.** Цвета переопределяются только в
    `:root[data-theme="dark"]`; шкалы (`--r-*`, `--sp-*`, `--fs-*`, `--e-*`)
    — на голом `:root`. Не класть шкалы внутрь селектора темы: до Записи 42
    они лежали в `:root[data-theme="light"]`, из-за чего переключатель тем не
    мог работать в принципе. Светлая тема — по умолчанию.
18. **Фиолетовый (`--color-ai`) — только для AI-состояний:** активная модель,
    режимы «Агент»/«Адаптивный», иконка панели агента, AI CTO. Навигация,
    кнопки, границы, активные строки — графит (`--color-accent`).
19. **`index.html` красит только `<html>`.** Инлайновый CSS не в слое и
    перебивает `@layer base`, поэтому покраска `body` там ломала фон приложения.
20. **Safari-UA в подписках — per-site, не глобально** (`store.subsSafariUa`).
    Он нужен для входа через Google, но ломает композер ChatGPT. См. Запись 42.
21. **Значения памяти от модели пропускать через `asText()`** (`memory.ts`,
    `handoff.ts`). JSON провайдера отдаёт массивы и объекты там, где тип
    обещает строку; сырое значение роняло панель памяти на `.trim()`
    (Запись 44). UI тоже не должен доверять типу.
22. **ChatGPT в подписках открывается в системном браузере** (`external: true`).
    Во встроенном WKWebView его композер не работает ни с Safari-UA, ни без.
23. **DTO через мост Tauri — только camelCase** (`#[serde(rename_all = "camelCase")]`).
    `DirEntry` отдавал `is_dir`, фронт читал `isDir`, поле было `undefined`, и
    все папки в дереве вели себя как файлы (Запись 45). Компилятор такое
    расхождение не ловит ни с одной стороны.
24. **Режим инструментов помечать только по факту.** Модель считается `react`
    исключительно если она НАПИСАЛА вызов текстом (`parseTextToolCall`), и
    `native` — если реально вызвала. Проза без вызова не значит ничего:
    прежняя эвристика `wantsTools()` клеймила хорошие модели после одного
    ответа, и пометка жила вечно (Запись 46). Сброс — `clearModelTools`,
    кнопка есть в `ModelSwitcher`.
25. **Рассуждения модели (`message.reasoning`) не попадают в канон.** Они не
    сохраняются в SQLite, не идут в резюме, в память проекта и обратно в
    модель. Это процесс, а не содержание ответа.
26. **Разрушительные действия — через `lib/guards.ts`.** `alwaysConfirm()`
    требует подтверждения независимо от `prefs.autoApplyEdits`: правка
    секретных файлов (`.env`, ключи, сертификаты), `delete_file`, опасные
    команды (`rm -rf`, `pkill`, `git reset --hard`…). Агент стёр живой токен
    из `.env`, потому что auto-apply распространялся и на него (Запись 47).
27. **Каждый агентский цикл обязан следить за зацикливанием** — `newLoopWatch()`
    + `checkLoop()` перед выполнением вызова. Бюджет шагов не предохранитель:
    40 повторов одной команды укладываются в него целиком.
28. **Сообщения во время прогона идут в `agentInterjections`**, а не запускают
    второй запрос. Цикл сливает очередь перед следующим обращением к модели —
    строго после блока результатов инструментов, иначе провайдер отвергнет
    структуру сообщений.
29. **«Идёт ли прогон агента» — только `store.agentRunning`.** Локальный
    `useState` в ChatView устаревал, и параллельные прогоны накладывались друг
    на друга (Запись 48). `send()` обязан читать флаг через `getState()`.
30. **Kimi — это `openai_compat`, а не отдельный `ProviderKind`.** В форме
    подключений он живёт как `FormKind`, чтобы подставить адрес и регион.
    Глобальный и китайский эндпоинты — разные сервисы с несовместимыми ключами.
31. **Агентские шаги идут через `agent_step_stream`.** Не-стримовый
    `agent_step` оставлен фолбэком для провайдеров без стрима (GigaChat).
    Сборка tool_calls различается: openai_compat — фрагменты по `index`,
    Anthropic — `content_block_start` + `input_json_delta` (Запись 49).
32. **Системный блок Anthropic всегда с `cache_control: ephemeral`** — он
    одинаков на всех шагах прогона, без кэша каждый шаг переоплачивается.
33. **Буфер обмена — только через `lib/clipboard.ts::copyText()`**, и результат
    обязан быть виден пользователю. `navigator.clipboard` в webview отказывает
    без user gesture; прежний код глотал отказ в `console.error`, и кнопка
    «Скопировать контекст» молча не делала ничего (Запись 43).
34. **Память проекта — это факты, а не текст.** Единица хранения —
    `memory_facts` (`lib/facts.ts`): вид, текст, происхождение, спека проверки,
    статус, дата проверки. Старые колонки `projects` (`tech_stack`,
    `architecture_notes`, `coding_standards`, `risks`, `active_goals`,
    `last_state`) один раз разбираются на факты и **в промпт больше не идут** —
    они остались в БД как страховка. Не возвращать запись в них: ложный факт
    хуже отсутствующего, потому что ему доверяют, и без происхождения его
    нечем отличить от проверенного (Запись 50).
35. **Ничто не рождается проверенным.** `newFact()` всегда ставит
    `unverified`; статус меняет только `lib/verify.ts`, то есть машина. Модель
    к проверке собственной памяти не подпускается — она согласится сама с
    собой. Ручная правка факта сбрасывает подтверждение: проверка стояла за
    прежней формулировкой.
36. **Решения — события, а не поле.** `decisions` (таблица) + `lib/decisions.ts`:
    что, когда, почему, что отвергли, какие файлы, при каком коммите. Это
    главный дифференциатор продукта; не сворачивать обратно в текст.
37. **В промпт уходит отобранная память, а не вся.** `buildProjectMemory(session,
    query)` → `lib/relevance.ts`. Ограничения и стек целиком, остальное — по
    близости к запросу, с жёстким потолком в символах. Отбор обязан оставаться
    лексическим и локальным: он работает на каждом ходу. И в промпте должно
    оставаться явное «показана только релевантная часть», иначе отсутствие
    факта читается моделью как пустая память.
38. **Расхождения памяти и кода копятся, а не прерывают.** `flag_memory` кладёт
    заметку в `divergences` и сразу возвращает управление; опровергнутые
    проверкой факты идут туда же. Никаких модалок посреди прогона: усталость от
    подтверждений уже привела к отключённому спросу и `pkill` без
    предупреждения (Записи 47, 50).
39. **Новый агентский инструмент прописывается в трёх местах:** `AGENT_TOOLS`,
    `REACT_SYSTEM`, `summarizeArgs` (+ иконка в `AgentTrace`). Пропуск
    `REACT_SYSTEM` означает, что инструмента не существует для моделей без
    function-calling.
40. **Потоки байтов декодировать через `utf8::Utf8Stream`.** `String::from_utf8_lossy`
    на каждом сетевом чанке рвёт любой многобайтовый символ, попавший на границу:
    у пользователя в ответе появлялось `Ток<?><?>н`. Правило распространяется на
    все пять стримов провайдеров, вывод `run_bash` и PTY (Запись 51).
41. **Ложное опровержение факта хуже отсутствия проверки.** Шаблон грепа
    строится из значимых токенов (`lib/verifyspec.ts`): имя пакета → продукт →
    версия → редкое слово, классы не смешиваются. Если ни один кандидат не
    годится — спека не создаётся, факт честно остаётся непроверенным. Перед тем
    как пометить факт `refuted`, ищем по всему проекту: модель чаще ошибается
    именем файла, чем сутью (Запись 51).
42. **Анализ папки без сигналов не зовёт модель.** Нет ключевых файлов — проект
    получает имя папки и пустую память. Слабая модель без сигналов пересказывает
    выданную ей инструкцию, и «Outputs raw JSON format» оказывается в памяти как
    стек проекта (Запись 51).
43. **Повторный анализ заменяет, а не добавляет.** Удаляются прежние факты
    `extracted`/`inferred` этого проекта, кроме факта «где остановились».
    Пользовательские и legacy-факты не трогаются. Иначе каждое нажатие кнопки
    множит память на копии — и в панели, и в промпте.
44. **Перетаскивание файлов — через `getCurrentWebview().onDragDropEvent()`.**
    Tauri перехватывает drop на уровне окна, HTML5-события до React не доходят.
    Событие отдаёт настоящие пути; картинки идут изображениями, PDF — извлечённым
    текстом, остальное — содержимым файла.
45. **UI не обещает того, чего нет.** Строка «ключи в Keychain» держалась в
    интерфейсе ещё долго после перехода на `secrets.json` — а файл не зашифрован.
    На таких строках люди принимают решения о безопасности; текст обязан
    соответствовать коду (Запись 51).

46. **Замена по проекту — только через точный подсчёт, не через BM25.**
    Ранжированный индекс матчит слова: он не знает, сколько точных вхождений в
    файле, и замена по его выдаче правит то, чего пользователь не видел.
    `lib/replace.ts`: grep сужает круг файлов, вхождения считаются в самом
    файле, список с числами показывается до записи. Отката нет — только git.
47. **Маркеры проверок ставятся под одним владельцем** (`magnetar-checks`),
    иначе результаты прогонов накапливаются друг на друге. Синхронизация — и на
    завершение проверки, и на открытие вкладки: проблема из закрытого файла
    должна появиться при открытии (Запись 52).
---
48. **Помощникам запрещено делегировать и спрашивать пользователя.** Мосты
    `askUser` и `teamCtx` сохраняются и восстанавливаются вокруг каждого
    прогона (помощник идёт через ту же `runAgent`), а список инструментов
    прокидывается **параметром**: модульная переменная сломалась бы при
    параллельных прогонах. Разрушительное помощникам отказывается сразу, а не
    подтверждается — три параллельных запроса разрешения учат нажимать
    «разрешить» не читая (Записи 47, 53).
49. **Задача субагента объявляет файлы, и пересечения не стартуют**
    (`lib/leases.ts`). Побеждает вторая запись, поэтому «пусть разберутся сами»
    означает молча потерянную работу первого.
50. **Новое поле `Prefs` обязано пережить старый localStorage.** `persist`
    заменяет объект сохранённым, поэтому ключ, которого не было вчера, приходит
    `undefined` — и первый же компонент, читающий его, роняет панель через error
    boundary (`subagentRoster`, Запись 54). В `persist` есть `merge`: сначала
    `DEFAULT_PREFS`, поверх сохранённое. В компоненте всё равно ставить `?? []`.
51. **Куда писать новый проект, решает приложение, а не модель.** `new_project`
    принимает только имя; путь фиксирован (`~/Documents/Magnetar/<имя>`),
    существующее имя получает суффикс, папка открывается как проект целиком
    (дерево, индекс, память). Дай модели выбирать путь — она снова начнёт
    угадывать, и страница окажется в чужом репозитории (Запись 54).
52. **Без открытой папки агент не ищет проект по диску.** Блок в
    `buildProjectMemory` говорит прямо: проекта нет, искать не надо, найденное
    так будет не тем. Запрета на запись мало — модель продолжает сканировать
    `/Users`, пока ей не сказано, что это не её работа.
53. **Защита — это не отказ пользователя.** Статус `blocked` (зацикливание,
    запрет помощнику) отличается от `declined` (человек нажал «Отклонить»).
    Показывать одно как другое — врать пользователю о том, чего он не делал.

## 3. Архитектура интерфейса (после Записи 32)

## 6. Подпись сборки (иначе macOS требует пароль каждый раз)

Приложение по умолчанию **не подписано**, поэтому у него нет стабильной
идентичности: macOS считает каждую пересборку другой программой, ACL Keychain
не совпадает, «Всегда разрешать» не запоминается и пароль спрашивается снова.

Один раз (запускает **пользователь** — трогает его Keychain и требует пароль):

```bash
bash scripts/setup-signing.sh
```

Идентичность «Magnetar Dev» у пользователя **уже создана** (2026-08-19), так что
обычно достаточно `sign-app.sh`. ⚠️ Скрипт правился в Записи 42: он обязан звать
системный `/usr/bin/openssl` (LibreSSL) и писать PKCS#12 со старыми алгоритмами
(`PBE-SHA1-3DES`, `-macalg sha1`). Homebrew OpenSSL 3 создаёт контейнер, который
Keychain не читает, и падает с обманчивым «wrong password?».

После каждой сборки:

```bash
npm run tauri build && bash scripts/sign-app.sh
```

Это локальный dev-сертификат «Magnetar Dev», не Apple Developer ID:
нотаризации нет, на другие машины так не распространить. Ассистенту
`setup-signing.sh` запускать нельзя — это изменение настроек безопасности.

## 9. Как проверить, что уходит модели

Кнопка «глаз» в шапке панели агента → **«Что видит модель»**: полный системный
контекст последнего запроса (`store.lastContext`). Первым делом смотреть туда —
она отвечает на вопросы «дошла ли память», «знает ли агент корень проекта»,
«попал ли файл, добавленный через @».

Чистая проверка памяти: вписать в Проекты → «Ключевые решения» факт, которого
нет в коде, и спросить о нём другую модель. В dev-режиме доступен
`window.__magnetar` (zustand store) для инспекции состояния из консоли.

## 9a. Диагностика: «модель не видит проект»

**Сначала проверьте, не тот ли это баг, что чинили в Записи 36.** Режим агента
теперь определяется автоматически: `store.modelTools` запоминает, вызывает ли
модель инструменты по-настоящему. Если модель не умеет function-calling,
приложение само переигрывает ход через текстовый ReAct. **Не возвращать выбор
режима по `connection.kind`** — шлюзы принимают `tools` и для моделей, которые
их игнорируют, и агент молча завершался после первого шага.

Также помните: пути от модели (`"/"`, `"."`, относительные) резолвятся в
`workspaceRoot` через `resolvePath` в `agent.ts` — без этого `list_dir {"path":"/"}`
листает корень файловой системы.


Частый сценарий поддержки. Проверять по порядку:

1. **Включён ли «Агент»** (pill в панели агента / статус-бар). Выключен →
   инструментов нет, модель честно скажет, что файлов не видит. Это не баг.
2. **Доступна ли модель.** 403 вида `This token has no access to model …` —
   ответ провайдера. Настройки → «Проверить» на подключении подберёт рабочую
   модель. Пока модель недоступна, **анализ папки в память тоже не отработает**
   — он использует `cheapModel()`, который откатывается на активную модель.
3. **Собралась ли память проекта.** Проект с именем-заглушкой и пустыми полями
   = анализ провалился. Причина теперь видна алертом в панели «Файлы»
   («Память проекта не собрана») + кнопка «Повторить анализ».
4. **GigaChat**: native tool-use у него нет, работает через текстовый ReAct
   (`REACT_SYSTEM` в `agent.ts`). Список инструментов там задаётся текстом —
   при добавлении нового инструмента его надо прописать И в `AGENT_TOOLS`,
   И в `REACT_SYSTEM`, иначе ReAct-провайдеры о нём не узнают.

Корень воркспейса всегда уходит агенту через `buildProjectMemory`
(`## Workspace root`) — независимо от того, заполнена память проекта или нет.

## 10. Как агент работает с моделями (важно понимать)

Режим определяется **фактом, а не типом подключения** (`store.modelTools`):

- первый агентский ход: модель вызвала инструмент → `native`, запоминаем;
- не вызвала, а запрос был про проект (`wantsTools()`) → `react`, ход
  немедленно переигрывается через текстовый ReAct, и так далее всегда.

Причина: шлюзы (OpenRouter и др.) принимают поле `tools` даже для моделей без
function-calling, те его игнорируют, и агент молча завершался после первого шага
(«не вижу файлы»). Это чинилось в Записи 36 — **не возвращать выбор режима по
`connection.kind`**.

В `ModelSwitcher` режим показан значком: 🔧 native, 💬 ReAct, ⊘ отказано.

Пути от модели (`"/"`, `"."`, относительные) резолвятся в `workspaceRoot`
через `resolvePath` в `agent.ts`. Парсер ReAct принимает и «голый» вызов вида
`list_dir {"path":"."}` без обвязки `Action:` — слабые модели пишут именно так.

**Провайдеры:** OpenAI-совместимый (OpenRouter, Kimi, локальные), GigaChat,
**Anthropic** (нативный: `x-api-key`, `/v1/messages`, `tool_use`-блоки — см.
Запись 38; подключать только через кнопку «Claude (Anthropic)», OpenAI-режим
даёт 401 «Invalid bearer token»).

Практика по моделям: `-free`-эндпоинты Qwen/DeepSeek на OpenRouter отдавали
404/503 и не держали инструменты. Для длинных задач нужны модели с native
tool-use. GigaChat function-calling не имеет — всегда ReAct.

## 11. Monaco: чего нельзя ломать

- Загрузчик `@monaco-editor/react` **обязан** указывать на локальный monaco
  (`loader.config({ monaco })` в `src/lib/monaco.ts`) — иначе он полезет на CDN
  и приложение перестанет работать офлайн.
- В monaco-editor 0.56 пути `monaco-editor/esm/vs/...` **не резолвятся**
  (пакет перешёл на exports-map). Воркеры импортируются как
  `monaco-editor/editor/editor.worker?worker` и
  `monaco-editor/languages/features/<lang>/<lang>.worker?worker`.
- TypeScript-сервис живёт в `monaco.typescript`, а не в
  `monaco.languages.typescript` (последний помечен deprecated).
- Семантическая валидация TS выключена намеренно: без реального графа проекта
  каждый импорт подсвечивался бы как ошибка.
- CSP в `tauri.conf.json` = `null`. Если его включат, Monaco потребует
  `worker-src blob:`.
- `src/lib/monaco.ts` больше **не** импортируется в `main.tsx`: движок грузится
  лениво через `loadMonaco()`. `EditorArea` обязан вызвать `loadMonaco()` и
  дождаться `monacoReady` **до** монтирования `<Editor>`/`<DiffView>`, иначе
  `@monaco-editor/react` не найдёт локальный monaco и полезет на CDN. Тема
  передаётся лениво через `setMonacoTheme` (запоминает `pendingTheme`).
