# План работ до публикации

> Составлен 2026-08-21 по итогам аудита возможностей IDE. Порядок этапов —
> сверху вниз, следующий не начинается, пока не закрыт предыдущий.
>
> Общий срок: **15–23 рабочих дня** до подписанного и нотаризованного релиза.

---

## Принцип порядка

Сначала — дешёвое и заметное. Потом — то, чего нет у конкурентов (агент и
память). Потом — то, что есть у всех и работает одинаково (языковой
интеллект). В конце — обвязка публикации.

Причина такого порядка: если релиз не завтра, разумнее сначала усилить своё
отличие, чем догонять чужой паритет. Языковые серверы — работа, которую все
делают одинаково, и она никого не удивит; память проекта и оркестрация агентов
— то, ради чего продукт существует.

---

## Этап 1. Долги редактора (1–2 дня)

Дешёвые вещи, которые сейчас читаются как недоделка.

| Работа | Почему |
|---|---|
| Ошибки из «Проблем» — маркерами в редакторе (`setModelMarkers`) | Данные уже есть: файл, строка, колонка, сообщение. Не хватает одного вызова, а разница в восприятии огромная — сейчас ошибки живут в панели, а не в коде |
| Замена по проекту в панели поиска | Базовая операция, которой нет вообще |
| Быстрый переход к файлу (⌘P) | Ожидается всеми, кто работал в любом редакторе |
| Удалить мёртвые зависимости | Девять пакетов CodeMirror не используются в коде нигде |

Механизм маркеров переиспользуется на этапе 3: языковые серверы станут просто
ещё одним их источником.

**Готово, когда:** ошибка из `cargo check` подчёркнута в коде, замена по проекту
работает с предпросмотром, ⌘P открывает файл по части имени.

## Этап 2. Субагенты (4–6 дней)

Главный агент раскладывает задачу, раздаёт помощникам, принимает результат и
собирает воедино. Существующий `/team` — не это: там жёсткая цепочка из трёх
промптов одной модели, без распределения и без параллельности.

**Состав работы**

1. **Оркестрация.** Инструмент `delegate(task, files, model?)` у главного плюс
   ожидание результатов. Субагент — обычный агентский цикл, который уже есть.
   Главный сам код не пишет: оркестратор, который правит файлы, конкурирует со
   своими же подчинёнными.
2. **Аренда файлов.** Субагент объявляет, какие файлы берёт; пересечения
   запрещаются. Без этого двое правят один файл и затирают друг друга — это не
   риск, это первый же прогон.
3. **Отчёты вместо транскриптов.** Субагент возвращает что сделал, какие файлы
   тронул, что осталось. Полный диалог взорвёт контекст главного на третьем
   помощнике и будет оплачен дважды.
4. **Разрушительное — только через главного.** Субагентам опасные команды и
   правка секретных файлов запрещены жёстко, а не по подтверждению; всё такое
   эскалируется главному, пользователя спрашивают один раз. Подтверждения от
   шести агентов сразу — прямая дорога к «разрешить всё», последствия уже
   известны (Запись 47).
5. **Общий бюджет на команду**, а не на каждого: восемь агентов по сорок шагов
   — это триста двадцать вызовов инструментов.
6. **Панель дорожек.** Кто над чем работает, на каком шаге, что сдал. Иначе
   параллельные прогоны — чёрный ящик, который нельзя ни понять, ни осмысленно
   остановить.
7. **Пул прогонов** вместо одного глобального признака занятости.

**Ограничение по умолчанию:** три параллельных прогона при любом числе задач,
настройкой до пяти. Провайдеры лимитируют частоту, память уходит каждому, и
человек не следит за восемью потоками.

**Готово, когда:** задача «сделай три независимых экрана» выполняется тремя
помощниками параллельно, файлы не конфликтуют, в панели видно каждого, «Стоп»
останавливает всех.

## Этап 3. Языковой интеллект (8–13 дней)

Поднимает оценку по шкале IDE с 4 до 8. Всё недостающее — переход к
определению, ссылки, переименование, hover, автодополнение, семантические
ошибки, символы — это **одна деталь, а не шесть**: протокол языковых серверов.

### 3.1 Мост (2–3 дня)

Менеджер процессов на стороне Rust: запуск сервера как дочернего процесса,
JSON-RPC поверх stdio, маршрутизация по id, уведомления во фронтенд, перезапуск
упавшего. Обнаружение серверов в `PATH` — бандлить чужие бинарники не будем:
лицензии, десятки мегабайт и обязанность их обновлять. Синхронизация документов
со вкладками редактора.

**Готово, когда:** `rust-analyzer` поднимается на этом репозитории и принимает
открытый документ.

### 3.2 Функции в редакторе (2–3 дня)

Переход к определению и к типу, поиск ссылок с панелью результатов,
переименование по всему проекту, hover, автодополнение с авто-импортом,
подсказки параметров, символы документа (outline и breadcrumbs), переход к
символу по проекту, быстрые исправления и рефакторинги, форматирование.

**Готово, когда:** ⌘-клик по `db.saveFacts` в `store.ts` открывает `db.ts`,
переименование меняет все файлы, hover показывает тип.

### 3.3 Диагностика в реальном времени (1 день)

`publishDiagnostics` → маркеры в коде, пока печатаешь. Панель «Проблемы»
становится общим списком: серверы плюс то, чего они не знают — тесты и
произвольные проверки. Счётчик в статус-баре.

### 3.4 Четыре языка (1–2 дня)

TypeScript/JavaScript (заменяет нынешний одиночный воркер, снимая ограничение
«только открытый файл»), Rust, Python, Go. Плюс честное сообщение в интерфейсе,
когда сервер не установлен, вместо молчаливого отсутствия функций.

### 3.5 Устойчивость (1–2 дня)

Отмена устаревших запросов, перезапуск упавшего сервера без перезапуска
приложения, таймауты и потолок памяти, корректная работа на проекте, где
языкового сервера нет вовсе.

**Готово, когда:** повторный аудит по тем же двенадцати пунктам даёт «полностью
реализовано» по восьми языковым функциям для четырёх языков.

## Этап 4. Обвязка публикации (1–2 дня, без Apple-аккаунта)

Цель: в день покупки аккаунта остаётся вставить сертификат и запустить одну
команду.

1. **Universal-сборка.** Сейчас бинарник только x86_64 — на Apple Silicon он
   идёт через Rosetta. Оба Rust-таргета уже установлены.
2. **Секция `bundle.macOS`**: минимальная версия системы, путь к entitlements,
   место под идентичность подписи. Сейчас секции нет вовсе.
3. **Entitlements и hardened runtime — проверить сегодня.** Подписать текущим
   локальным сертификатом с `--options runtime` и запустить. Если вебвью не
   стартует под hardened runtime, это выяснится сейчас, а не в день релиза.
4. **`scripts/release.sh`**: сборка → подпись → нотаризация → staple → DMG.
   Учётные данные из переменных окружения; без них скрипт останавливается с
   внятным сообщением.
5. **Синхронизация версии** — она живёт в `tauri.conf.json` и `Cargo.toml` и
   может разъехаться.
6. **LICENSE** — в репозитории его нет.

---

## Этап 5. День покупки аккаунта (2–3 часа)

Сертификат Developer ID и пароль для нотаризации — руками владельца, это
доступ к Keychain. Затем `scripts/release.sh` и проверка на чистом профиле:
скачанный DMG открывается без правого клика и без предупреждений Gatekeeper.

**Публикация только через Developer ID, не через App Store.** App Store требует
sandbox, а приложение запускает произвольные команды, читает любые папки и
поднимает PTY. В sandbox это невозможно.

## Открытые вопросы

Работа не блокируется — по каждому есть значение по умолчанию, но лучше решить
заранее.

| Вопрос | По умолчанию |
|---|---|
| **Автообновления.** Публичный ключ вшивается в приложение, поэтому решать надо до первого релиза: иначе первые пользователи останутся на первой версии навсегда | Включить, GitHub Releases как хранилище |
| Разные модели для главного и помощников | Да: главный сильный, помощники дешёвые |
| Может ли главный агент сам править файлы | Нет, только раздаёт и собирает |
| Потолок параллельности | Три, настройкой до пяти |
| Клиент языковых серверов | Свой тонкий (~600–900 строк), не `monaco-languageclient`: тот тянет подмену Monaco целиком и рискует сломать работающий редактор |

---

## Что не входит

Отладчик с точками останова, маркетплейс расширений, удалённая разработка по
SSH, ноутбуки. Каждая из этих вещей — отдельный продукт по объёму, и ни одна не
усиливает то, ради чего Magnetar существует.

---

## Правила работы по этапам

После каждого этапа: `npx tsc --noEmit`, `npm run build`,
`cd src-tauri && cargo check`, `cargo test`; новый ключ i18n — сразу в ru/en/es;
запись в `HANDOFF.md` и обновление `NEXT_TASK_FILES.md`. Новый баг сначала
воспроизводится тестом, потом чинится.
