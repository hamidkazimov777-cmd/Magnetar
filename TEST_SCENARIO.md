# Тест-сценарий Magnetar — «работает ли всё как задумано»

Тест на двух уровнях: **(A) авто-тест движка** (его прогоняю я по твоим API-ключам)
и **(B) живой тест в приложении** (его проходишь ты). Подписочные модели
(Claude/Gemini/GPT) — только в уровне B (через встроенный браузер + мост контекста),
т.к. у подписки нет API.

---

## A. Авто-тест движка (запускаю я)

Проверяет детерминированно: подключение моделей, чат, tool-use, **межмодельный
handoff** (новая модель помнит контекст предыдущей) и **работу из памяти (summary)**.

**Что делаешь ты (1 шаг):**
1. Скопируй `.magnetar-test/keys.example.json` → `.magnetar-test/keys.json`.
2. Впиши 2–3 своих **API-ключа** (OpenAI-совместимые: OpenRouter/DeepSeek/GLM/Qwen).
   Файл в `.gitignore` — в git не попадёт, в чат ключи не вставляй.
3. Скажи «готово» — я запущу `node scripts/e2e-test.mjs` и покажу отчёт PASS/FAIL.

---

## B. Живой тест в приложении (проходишь ты)

### Шаг 1. Подключения
- Настройки → добавь 2–3 модели (API-ключи). Для подписок — вкладка «Подписки»,
  залогинься в ChatGPT/Claude/Gemini во встроенном браузере.
- **Ожидание:** модели появляются в переключателе сверху, есть поиск.

### Шаг 2. Онбординг проекта (память из папки)
- Вкладка «Код» → «Открыть папку» → выбери папку проекта.
- **Ожидание:** появляется «Анализирую проект…», затем во вкладке «Проекты»
  автоматически заполнены стек/архитектура/описание. Это память проекта.

### Шаг 3. Создать одностраничник (агент)
- Вкладка «Чат» → включи «Агент» → выбери модель (напр. Qwen).
- Промпт: «Создай в этой папке одностраничный сайт index.html: заголовок “Magnetar
  Demo”, секция hero, кнопка. Плюс style.css.»
- **Ожидание:** агент показывает шаги, на `write_file` — **окно подтверждения с
  diff** (зелёные строки). Разрешаешь → файлы создаются (проверь во вкладке «Код»).

### Шаг 4. Переключение модели (флаш в память)
- Переключи модель на другую (напр. DeepSeek) в переключателе сверху.
- **Ожидание:** на переключении фоном пишется «где остановились» в память проекта
  (вкладка «Проекты» → поле обновляется).

### Шаг 5. Продолжение из памяти
- Той же (новой) моделью: «Продолжи с того места, где остановилась предыдущая
  модель — добавь футер со ссылками».
- **Ожидание:** новая модель **не переспрашивает про весь проект**, а продолжает:
  ссылается на уже созданные index.html/style.css, добавляет футер. Это и есть
  «память проекта, а не перечитывание».

### Шаг 6. Подписочная модель через мост
- Вкладка «Подписки» → «Скопировать контекст проекта» → вставь в ChatGPT/Claude в
  браузере → получи ответ → «Добавить в канон».
- **Ожидание:** подписочная модель работает с тем же контекстом; её ответ попадает
  в общую память.

### На что смотреть (поведение моделей)
- Континуитет при смене модели (не начинает с нуля).
- Уважает подтверждения на разрушающих действиях.
- «Стоп» реально останавливает (в т.ч. долгие команды в терминале).
- Адаптивный режим: на «привет» — лёгкая модель, на «создай приложение» — предлагает сильнее.
